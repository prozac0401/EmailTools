# EmailTools 2.1 개발 스펙 · 작업 목적과 항목 탐색

작성일: 2026-09-09 · 상태: 개발 전 설계안 v7 · 자동 줄바꿈 버튼, 상세 툴팁과 보이는 드래그 이동

이 문서는 다음 개발의 기준을 제안한다. 현재 배포 기능을 설명하는 사용자 매뉴얼이 아니다. 이번 설계 작업은 실행 코드와 기존 결과 형식을 변경하지 않는다.

## 1. 목표와 범위

사용자가 먼저 원하는 결과를 고르고, 필요한 작업만 실행하며, 여러 문서에서 나온 표 항목을 근거와 함께 선택하게 한다.

성공 조건:

- 메일 목록만 필요한 사람은 표 설정이나 첨부 내용 분석을 거치지 않고 목록을 저장한다.
- 첨부 정리가 필요한 사람은 어떤 메일의 어떤 첨부가 저장되었는지 목록으로 확인한다.
- 표 분석이 필요한 사람은 수백 개 항목을 처음부터 읽지 않고 공통 후보와 대표 값을 살펴볼 수 있다.
- 드문 항목도 발견 가능하며, 추천이나 화면 필터가 저장할 열을 몰래 바꾸지 않는다.
- 항목명과 데이터는 기본 14px 이상으로 읽을 수 있다.

입력은 현재 제품의 로컬 EML 파일/폴더와 브라우저 EML 업로드를 기준으로 한다. 여기서 ‘목록 가져오기’는 EML에서 목록을 만드는 뜻이다. Outlook/Gmail 계정에서 메일 목록을 직접 가져오는 연결 기능은 별도 후속 범위다. DOCX는 EML 첨부를 대상으로 하며 독립 Word 파일 입력도 후속 범위다.

## 2. 현재 구조에서 바꿔야 하는 점

| 현재 동작 | 개선 요구 |
|---|---|
| 기본 작업이 네 가지 처리 옵션 체크박스 조합 | 세 가지 작업 목적을 먼저 선택하고 세부 옵션은 접는다 |
| 네 처리 옵션이 모두 꺼져 있으면 실행 불가 | 목록 생성만으로 유효한 작업을 구성한다 |
| 표와 관계없이 본문을 렌더링하고 모든 첨부 payload를 디코딩 | 목록 모드는 헤더와 MIME 메타데이터만 사용한다 |
| 모든 추출 열을 최초 등장 순서로 선택 | 탐색 정렬과 저장 열 선택을 분리한다 |
| 각 표 행을 두 칸씩 항목/값으로 해석 | 표 구조를 구분하고 불명확한 표를 별도로 검토한다 |
| 동일 항목/값을 합치면서 반복과 출처 소실 | 원본 등장 기록을 보존한 뒤 집계와 결과 투영을 수행한다 |
| 목록은 summary.csv 중심, Excel은 표 기능에 종속 | 목록만 Excel로 저장할 수 있게 한다 |
| 항목/표 12px, 머리글 11px, 일부 안내 9px | 통일된 글자 크기와 행 높이를 적용한다 |

근거 코드: `models.py`, `pipeline.py`, `extractors/tables.py`, `table_config.py`, `exporters/files.py`, `ui/server.py`, `ui/static/ui.js`, `ui/static/ui.css`.

## 3. 기본 작업 세 가지

처음 실행할 때 ‘메일 목록만’을 선택 상태로 둔다. 세 카드에는 아래 이름, 목적, 대표 산출물만 표시한다. 선택만으로 처리를 시작하지 않는다.

| 구분 | 메일 목록만 | 목록과 첨부 정리 | 목록·첨부·표 분석 |
|---|---|---|---|
| 설명 | 제목·발신자·날짜를 한눈에 정리 | 목록과 함께 첨부 원본을 메일별로 저장 | 본문과 Word 첨부의 표 항목까지 비교·선택 |
| 메일 목록 | 포함 | 포함 | 포함 |
| 첨부 개수 | 포함 | 포함 | 포함 |
| 첨부 상세 목록 | 메일 상세에서 이름 확인 | 포함 | 포함 |
| 첨부 원본 저장 | 꺼짐 | 켜짐 | 켜짐 |
| HTML 본문 표 분석 | 꺼짐 | 꺼짐 | 켜짐 |
| DOCX 첨부 표 분석 | 꺼짐 | 꺼짐 | 켜짐 |
| 본문 TXT 저장 | 꺼짐 | 꺼짐 | 꺼짐 |
| 첨부 내용 TXT 추출 | 꺼짐 | 꺼짐 | 꺼짐 |
| 검토 첫 화면 | 메일 목록 | 첨부파일 | 표 항목 찾기 |
| 기본 결과 | 메일 목록 Excel | 목록 Excel + 첨부 원본 | 목록 Excel + 첨부 원본 + 선택한 표 Excel |

‘목록·첨부·표 분석’의 카피에는 표 분석 대상을 반드시 적는다. PDF/XLSX/PPTX까지 구조화된 표를 추출한다고 보이게 하지 않는다. 첨부 텍스트 추출은 기본 작업과 별개다.

추가 옵션은 작업 선택 아래 ‘세부 설정’에 둔다.

- 본문을 TXT로 함께 저장.
- 첨부 내용을 TXT로 추출: 기존 지원 형식 사용. OCR은 하지 않음.
- 첨부 원본 저장, 첨부 상세 목록 포함.
- 표 분석 사용 및 대상: 메일 본문 / Word 첨부. 표 분석을 켜면 최소 하나 선택.
- ‘표만 취합’ 빠른 설정: 목록은 공통 제공, 첨부 원본·본문·첨부 텍스트 저장은 끄고 표 분석만 켠다. 기존 사용자 경로 보존용이다.

기본 카드와 다른 옵션을 선택하면 카드 선택은 유지하고 ‘세부 설정 변경됨’을 표시한다. 하단에는 실제 결과 구성으로 계산한 ‘저장 예정’을 항상 표시한다. 다른 카드를 누르면 해당 카드 기본값으로 바뀌며 선택 내용을 즉시 보여준다.

## 4. 정보 구조와 화면 흐름

### 4.1 작업 선택

화면 순서:

1. 제목 ‘어떤 결과가 필요한가요?’와 작업 카드 세 개.
2. ‘메일 불러오기’: 폴더 선택, EML 파일 선택, 경로 입력, Drag & Drop. 샘플은 보조 버튼.
3. 접힌 ‘세부 설정’과 펼치지 않아도 보이는 저장 예정 요약.
4. 주 버튼: 표 분석을 켰으면 ‘표까지 분석하기’, 그 외에는 ‘목록 만들기’.

입력 전에는 실행 버튼을 비활성화하고 ‘EML 파일 또는 폴더를 선택해 주세요’를 가까이 표시한다. 브라우저 파일 선택과 로컬 경로 입력의 기존 용량 제한을 적용한다. 이 단계에서는 저장 위치를 묻지 않는다.

### 4.2 처리 중 · Progress Bar 필수

목록 생성, 첨부 준비, 표 분석, 재분석, 결과 저장에 공통 진행 영역을 사용한다. 상단의 ‘작업 선택 → 결과 검토 → 저장 확인’은 화면 이동 경로이며 실제 처리 진행률과 구별한다.

진행 영역은 작업 이름 → 실행 단계 목록 → 현재 단계/처리 비율 → 가로 진행 표시줄 → 처리 개수/현재 파일/경과 시간 → 중지 순으로 배치한다. 작업 시작 직후 첫 서버 상태를 받기 전에도 ‘준비 중’을 표시한다. 완료할 때까지 진행 영역을 유지하며 결과가 없는 빈 화면으로 바뀌지 않는다.

| 단계 | 표시줄 | 표시할 내용 |
|---|---|---|
| 파일 찾기 | 전체량 미확정 | 발견한 EML N개 · 파일 찾는 중. 퍼센트 없음 |
| 메일 처리 | 확정된 메일 수 기준 | 현재 단계 60% · 처리한 메일 12/20개 · 현재 파일 |
| 항목 정리 | 고유 후보 수가 확정되면 항목 수 기준, 그 전에는 미확정 | 항목 80/100개 정리 · 현재 단계 80% |
| 목록/표 Excel 생성 | 출력 행 수 기준 | 결과 파일명 · 기록한 행 200/500개 |
| 첨부/본문/TXT 저장 | 예정 파일 수 또는 확정된 바이트 수 기준 | 파일 8/20개 또는 24/100 MB · 단위를 명시 |
| ZIP 생성 | 묶음 입력 파일 수 또는 읽은 바이트 수 기준 | 전체 결과 묶는 중 · 압축 크기를 분모로 추정하지 않음 |
| 저장 마무리 | 전체량 미확정 | 결과 확인 및 저장 마무리 중 |
| 완료 | 완료 표시 | 모든 단계와 결과 확정이 끝난 뒤 작업 완료 100% |

목록 모드는 ‘파일 찾기 → 메일 정보 읽기 → 결과 준비’, 첨부 정리는 ‘파일 찾기 → 메일·첨부 준비 → 결과 준비’, 표 분석은 ‘파일 찾기 → 메일·표 읽기 → 항목 정리 → 결과 준비’로 표시한다. 내용 TXT 추출을 선택했으면 해당 작업을 메일 처리 단계의 현재 작업에 표시한다. 선택하지 않은 단계는 생략한다. 하나의 메일을 여러 분석기에서 읽어도 처리한 메일 수는 한 번만 증가한다.

메일 진행률의 분자는 이번 메일의 선택된 처리가 끝난 메일 수다. 정상/확인 필요/읽기 실패를 포함한 처리 종료 수를 사용하고 각 상태 수는 따로 보여준다. 실패한 메일 때문에 분자가 멈추지 않으며, 처리 중인 메일은 완료 수에 미리 넣지 않는다. 전체 파일 검색을 끝내 분모를 확정한 뒤 메일 진행률을 계산한다. 입력이 0개면 ‘EML 파일이 없습니다’로 끝내며 0으로 나누거나 성공 100%를 표시하지 않는다.

단계마다 단위와 소요 시간이 다르므로 임의의 가중치를 합산한 전체 퍼센트는 v1에서 만들지 않는다. ‘2/4단계 · 메일·표 읽는 중’과 **현재 단계 퍼센트**를 함께 표시한다. 단계 전환 시 표시줄이 새 단계의 0% 또는 미확정 상태로 바뀌는 이유가 제목과 단계 목록에서 드러나야 한다. 어느 단계의 100%도 전체 작업 완료를 뜻하지 않는다. 서버가 분석 결과를 게시하거나 저장 폴더를 최종 확정한 뒤에만 ‘작업 완료 100%’를 표시한다.

퍼센트는 실제 완료 수를 기준으로 내림 계산한다. 시간에 따라 가짜로 증가시키거나 실제 작업 중에 99%를 유지하는 연출은 사용하지 않는다. 경과 시간은 표시하되 남은 시간 예측은 초기 범위에서 제외한다. 큰 첨부 하나를 처리하는 동안 메일 개수가 그대로일 수 있으므로 현재 첨부명과 ‘Word 표 읽는 중’ 등 세부 작업을 계속 표시한다.

‘처리 중지’/‘저장 중지’를 누르면 한 번만 요청하고 ‘중지 요청됨 · 현재 작업 정리 중’으로 바꾼다. 서버가 중지를 확정하기 전에는 ‘중지됨’으로 표시하지 않는다. 분석은 메일 또는 분석기의 안전한 경계, 저장은 행/파일/압축 청크 경계에서 중지하고 이번 실행의 미완성 결과를 정리한다. 최종 폴더 확정 구간에서는 중지 버튼을 비활성화하고 ‘저장 마무리 중’을 알린다. 확정 직전에 중지를 요청했더라도 최종 서버 상태가 완료이면 완료로 표시한다.

재분석은 성공 시에만 기존 완성 결과를 교체한다. 실패/중지 시 이전 결과와 항목 선택 상태를 유지한다. 저장 중지/실패 시에도 분석 결과와 저장 구성은 유지하여 다시 저장할 수 있다. 일부 입력 실패 후 완료한 작업은 ‘완료 · 일부 확인 필요’와 실패 수를 표시하고, 치명적 작업 오류는 ‘실패’와 재시도 동작을 제공한다.

실행 중에는 입력/작업 설정/열 선택/중복 실행·저장을 막고 진행 확인, 글자 크기, 중지를 제공한다. 완료 화면의 주 버튼은 분석일 때 ‘결과 검토’, 저장일 때 ‘결과 열기’다. 시안에서는 실제 파일을 만들지 않으므로 후자를 ‘저장 구성으로 돌아가기’로 표시한다.

접근성: 확정 진행에는 `role=progressbar`와 `aria-valuemin/max/now`, 단계·단위가 포함된 `aria-valuetext`를 제공한다. 미확정 진행에는 `aria-valuenow`를 제거한다. 단계 전환·중지·완료는 상태 알림으로 읽히게 하고 매 파일/매 퍼센트를 음성으로 반복하지 않는다. 움직임 감소 설정에서는 진행 효과를 정적으로 표시한다. 작은 화면에서도 단계/개수/중지 버튼이 잘리지 않아야 한다.

### 4.3 결과 검토

상단에는 작업 이름, 입력 요약, 완료/확인 필요 건수와 ‘작업 설정 변경’을 둔다.

| 탭 | 표시 조건 | 주요 내용 |
|---|---|---|
| 메일 목록 | 모든 작업 | 제목, 발신자, 수신자, 날짜, 첨부 개수, 처리 상태 |
| 첨부파일 | 상세 목록/원본 저장/텍스트 추출/표 분석 중 하나 사용 | 원본 메일, 첨부명, 형식, 크기, 선택된 처리 결과 |
| 표 항목 찾기 | 표 분석 사용 | 공통 후보·드문 항목·반복·출처 비교와 저장 열 선택 |
| 저장할 표 | 표 분석 사용 | 선택 열의 순서, 이름, 사용자 열과 전체 결과 미리보기 |

표 분석을 선택하지 않은 작업에는 빈 표 탭이나 표 경고를 보여주지 않는다. ‘표 없음’, ‘지원하지 않는 형식’, ‘읽기 실패’를 구별한다. 표가 없는 메일은 정상적인 입력이며 자체로 분석 실패가 아니다.

메일 검색: 제목/발신자/수신자/원본 파일명. 첨부 검색: 첨부명/원본 메일. 상태 필터: 전체/확인 필요. 이 검색은 조회만 바꾸며 저장 행 수는 바꾸지 않는다. 하단에 ‘검색과 관계없이 전체 N개 메일 저장’을 명시한다. 행 단위 저장 제외는 이번 범위에 넣지 않는다.

메일 상세에는 원본 식별 정보와 첨부 이름을 제공한다. 목록 모드에서 본문 미리보기는 명시적으로 요청할 때만 읽는다. 원본을 다시 읽을 수 없으면 헤더 목록은 유지하고 이유를 표시한다.

### 4.4 저장 확인

결과 검토의 ‘저장 구성 확인’으로 진입한다. 이 단계에서 처음 저장 위치와 산출물을 함께 보여준다.

- 메일 목록: 전체 N개 메일.
- 첨부 목록: N개 첨부, 포함 여부.
- 첨부 원본: 저장 가능 N개 / 실패 N개.
- 표 Excel: 전체 N행, 기본 정보 X열 + 추출 항목 Y열 + 사용자 Z열.
- 추가 결과: 본문 TXT, 첨부 TXT, 처리 기록.

경로 기본 제안은 기존 제품 규칙을 유지한다. 영구 경로 없이 다운로드만 받는 선택을 제공한다. ‘결과 저장’이 실제 쓰기를 실행하는 유일한 주 버튼이다. 선택한 산출물의 파일명과 개수를 확인하고 저장할 수 있어야 한다.

표를 분석했지만 선택 열이 없을 때에는 ‘항목을 선택해 주세요’와 ‘표 Excel 없이 목록·첨부만 저장’을 제공한다. 후자는 사용자가 명시적으로 표 산출물을 끄는 동작이다. 빈 Excel을 조용히 만들거나 저장 버튼 전체를 막지 않는다.

완료 후 결과 폴더/목록 Excel/표 Excel/전체 ZIP 중 실제 생성된 결과만 제공한다. 실패 항목이 있으면 ‘완료 · 일부 확인 필요’와 그 내역을 함께 제공한다.

‘결과 저장’을 누른 뒤에는 4.2의 진행 영역을 표시한다. 파일 작성/첨부 복사/ZIP/저장 확정을 실제 선택한 산출물에 맞춰 구성한다. 서버 결과 생성과 브라우저 파일 다운로드는 별개이며, 생성 100%를 브라우저 다운로드 완료로 표시하지 않는다. 다운로드는 기존 브라우저 다운로드 UI에 맡긴다.

## 5. 표 항목 찾기 UX

### 5.1 기본 상태

탐색 기본 화면은 **위쪽 ‘선택한 열 순서’, 아래쪽 ‘남은 후보’**를 함께 표시한다. 두 영역 모두 항목을 이름이 보이는 버튼 형태로 가로 배치하고, 공간이 부족하면 자동으로 다음 줄로 이어진다. 항목 목록에는 가로 스크롤을 두지 않는다. 추출 항목의 초기 선택은 0개이며, 기본 정보 `source_eml`, `subject`는 위쪽에 항상 표시한다. 표 산출물은 추출 항목 또는 사용자 열을 하나 이상 선택한 뒤 활성화한다. 선택 전 후보는 공통 후보 우선으로 정렬하며, 추천 이외 항목을 숨기지 않는다.

**선택된 항목은 후보 목록에서 즉시 숨긴다.** 후보 이름의 버튼(＋ 표시)을 누르면 마지막 열에 추가한다. 선택 영역으로 끌어 놓으면 표시된 삽입 위치에 추가한다. 선택된 열의 ‘×’를 누르거나 후보 영역으로 끌어 놓으면 해제하고 현재 검색·출처·분류 조건에 맞는 후보로 다시 표시한다. 기본 메일 정보 2열은 순서 이동만 가능하다. 후보 검색·필터·정렬과 관계없이 위쪽에는 선택한 모든 열을 유지한다. ‘선택한 항목 보기’ 필터는 별도로 두지 않는다.

후보 위에 ‘공통 후보 N개 추가’를 둔다. N은 현재 출처 범위에서 아직 선택하지 않은 공통 후보 수다. 검색/카테고리와 관계없이 해당 출처 범위 전체의 공통 후보를 선택에 추가하며, 클릭 직후 범위를 알린다. 남은 공통 후보가 0개면 버튼을 숨긴다. 모든 일괄 선택 직후 ‘선택 되돌리기’를 제공한다.

화면 높이 안에 두 목록과 저장 구성 확인 버튼을 유지한다. **줄바꿈된 항목이 영역 높이를 넘으면 각 목록 안에서만 세로 스크롤한다.** 행이 늘어도 페이지 전체가 길어지지 않는다. 각 영역의 제목·개수·검색·이동 안내는 목록 밖에 남는다. 드래그 중 목록의 위/아래 가장자리에 접근하면 해당 목록만 자동 스크롤한다. 일반 선택 변경은 후보의 스크롤 위치를 보존하고 새 선택은 선택 영역 안에서 보여준다. 검색·필터 변경은 후보 스크롤만 맨 위로 돌린다.

항목 버튼에는 이름과 조작에 필요한 표시만 남기고, 근거 정보는 ⓘ 툴팁에 넣는다.

| 정보 | 표시 예시 | 역할 |
|---|---|---|
| 항목명 | 교육명 | 항상 표시, 선택/이동 대상 |
| 순번 | 1, 2, 3… | 선택된 열에 표시, 줄바꿈 후에도 출력 순서 식별 |
| 발견 메일 수 | 18 / 20개 메일 | 툴팁, 얼마나 널리 발견되는지 |
| 문서 내 등장 | 대부분 1회 | 툴팁, 한 문서에서 반복되는지 |
| 값 예시 | 안전교육 · 신규교육 | 툴팁, 실제로 원하는 열인지 |
| 표시 이유 | 공통 후보 / 드문 항목 / 반복 많음 / 구조 확인 | 툴팁, 검토 순서의 근거 |
| 선택 동작 | 후보 이름＋ / 선택 열 × | 항상 표시, 추가/제외 |

긴 이름은 버튼 안에서 줄바꿈하고 툴팁에 전체 이름을 제공한다. 후보 이름은 추가, 선택된 열 이름은 이동 대상 지정/드래그 시작, ⓘ는 정보 확인, ×는 제외로 동작을 분리한다. 모든 후보를 선택하면 완료 안내를, 검색·필터에 맞는 남은 후보가 없으면 조건 초기화 동작을 제공한다.

### 5.2 탐색 도구

- 검색: 항목명 기본, ‘값도 검색’ 선택 시 전체 집계 값까지 검색. 대표 예시 몇 개만 검색하지 않는다.
- 필터: 전체 / 공통 후보 / 드문 항목 / 반복 많음 / 구조 확인. 수량은 현재 출처 범위의 미선택 후보만 센다. 분류는 겹칠 수 있으며 배지 수를 합계처럼 표시하지 않는다.
- 정렬: 공통 후보 우선 / 발견 메일 많은 순 / 문서 내 반복 적은 순 / 처음 발견한 순.
- 출처: 전체 / 메일 본문 / Word 첨부. 출처 변경은 통계·값 예시·추천을 다시 계산한다. 현재 출처 범위 표시를 유지한다.
- 검색·정렬·필터는 선택과 Excel 열 순서를 바꾸지 않는다. 검색/카테고리 필터는 통계 분모도 바꾸지 않는다.
- 출처 필터 역시 조회 전용이다. 저장할 값의 원천을 제한하려면 작업 설정의 표 분석 대상을 변경해 재분석한다. 필터 옆에 ‘조회만 변경’을 표시한다.
- 검색은 후보 바로 위에 유지한다. 분류·정렬·출처는 ‘필터·정렬’ 대화상자에서 조정하고, 현재 출처와 분류 및 표시 개수는 후보 제목 아래에 남긴다. 설정은 즉시 적용되며 닫기/Escape 후 기존 화면으로 돌아온다.

### 5.3 항목 정보 툴팁

선택된 열과 후보 모두 ⓘ에 마우스를 올리거나 키보드 초점을 두면 툴팁을 표시한다. 터치는 ⓘ 탭으로 표시하고 바깥 탭으로 닫는다. Escape로 닫을 수 있어야 한다. 툴팁 열기/닫기는 선택과 순서를 변경하지 않으며 화면 가장자리에 맞춰 위치를 조정한다. 정보 확인을 위해 목록을 다른 화면으로 바꾸거나 아래로 상세를 덧붙이지 않는다. 현재 출처 범위에 해당 항목이 없으면 그 사실을 안내한다.

기본 툴팁 내용:

- 항목명, 발견 메일 수, 원본 문서 수, 반복 분포, 값 채움 비율.
- 서로 다른 값 예시 최대 3개. 값이 모두 같은 경우 사실만 표시하고 자동 제외하지 않는다.
- 출처 예시 최대 2곳: 원본 EML 경로, 본문 또는 DOCX 파일명, 표 번호와 행 위치. 예시임을 명시한다.
- 추천 표시 이유: 예를 들어 ‘서로 다른 메일 18개 · 문서 90%에서 1회 · 값 있음 100%’.
- 툴팁은 읽기 전용이다. 전체 원본 비교 및 ‘이 표를 항목/값 형식으로 사용’ 같은 표 단위 판정은 기존 원본 검토 기능에서 수행한다. 원본 HTML은 실행하지 않으며 지정 이유와 되돌리기 요구를 유지한다.

### 5.4 저장할 표

기본 정보, 선택한 추출 항목, 사용자 열을 구분해 구성한다. 선택 순서를 처음 열 순서로 사용하고, 기존 선택의 순서는 추가 선택으로 바꾸지 않는다. 해제 후 다시 추가한 열은 끝에 붙인다. 일괄 선택 내 순서는 최초 발견 순으로 고정한다.

기존 열 이름 변경/순서 이동/사용자 열 추가와 수정/원본 전체 비교 기능을 보존한다. 다중 값을 `값1 | 값2`로 보존하는 기존 출력 방식도 유지하며 값이 충돌하면 출처에서 각각 확인한다.

**열 Drag & Drop을 기본 순서 편집 방식으로 제공한다.** ‘표 항목 찾기’와 ‘저장할 표’의 열 버튼 및 표 머리글에서 같은 순서를 조정한다. 마우스는 버튼/머리글의 이름 영역을 잡을 수 있고, 터치는 열 이름을 잡아 이동한다. ⓘ·×와 이동 도구는 드래그를 시작하지 않는다. 기본 정보/추출 항목/사용자 열 모두 서로 위치를 바꿀 수 있다. 순번을 표시하고 열 종류는 툴팁에 넣으며, 종류별 고정 영역으로 이동을 제한하지 않는다.

**열 버튼은 왼쪽부터 오른쪽으로 배치하고 공간이 부족하면 다음 줄로 이어진다.** ‘표 항목 찾기’와 ‘저장할 표’ 모두 같은 배치를 사용한다. 읽는 순서와 순번이 미리보기와 Excel의 왼쪽부터 순서에 대응한다. 화면 너비 변경으로 줄이 바뀌어도 저장된 순서는 변경하지 않는다. 드롭 위치는 먼저 포인터가 놓인 줄을 정한 뒤, 그 줄의 버튼 가운데를 기준으로 앞/뒤 삽입을 결정한다. 버튼 사이 공백과 마지막 버튼 이후 빈 영역에 놓는 경우도 처리한다. 두 항목 목록에는 가로 스크롤을 만들지 않으며 실제 미리보기 표는 기존 가로 열 배치를 유지한다.

시안과 제품 화면의 열 이동은 HTML5 `dragstart/drop`에만 의존하지 않고 Pointer Events와 pointer capture로 구현한다. iframe/WebView에 포함된 화면에서 마우스·펜·터치 입력을 검증한다. 눌렀다가 6px 이상 움직이면 이동을 시작하고, 놓을 때만 선택/순서를 확정한다. Escape, `pointercancel`, 캡처 상실, 창 포커스 상실 시 이동 모양과 삽입선을 정리하고 이전 선택/순서를 유지한다. 이동을 마친 뒤 발생하는 클릭이 후보를 다시 추가하지 않도록 구분한다.

**드래그 동안 버튼 모양이 포인터를 따라 이동한다.** 원래 크기와 이름을 유지한 복제 모양을 표시하고 원래 자리는 옅은 점선으로 남긴다. 복제 모양은 클릭과 드롭 판정을 가로채지 않는다. 놓일 위치는 버튼 앞/뒤의 세로 삽입선으로 표시한다. 후보에서 선택 영역으로 추가하거나 반대로 제외할 때에는 대상 영역도 강조한다. 미리보기 데이터와 실제 저장 순서는 놓기를 완료한 때 한 번 갱신하며, 드래그 중간 위치마다 서버 미리보기를 요청하지 않는다. 목록의 위아래 가장자리에서는 해당 목록만 세로 스크롤한다.

손잡이는 이름 변경/선택/열 너비 조절과 분리한다. 셀 내용에서 드래그할 때는 텍스트 선택을 유지한다. 같은 위치에 놓기, 목록 밖에 놓기, 외부 파일/텍스트 드롭, Escape 취소는 열 순서를 변경하지 않는다. 입력 EML의 Drag & Drop 영역과 열 이동을 혼동하지 않게 내부 열 ID와 현재 데이터셋으로 이동을 검증한다.

이동 직후 ‘교육명을 2번째 열로 이동했습니다’와 ‘순서 되돌리기’를 제공한다. 되돌리기는 직전 순서 변경 한 번을 복원한다. 그 뒤 열 추가/제외 또는 데이터셋 변경이 있으면 이 되돌리기는 종료하며, 같은 데이터셋에서 탐색 필터/탭만 바꿨을 때에는 유지한다. 선택 영역 안에서의 순서 이동은 값, 열 이름, 선택 개수, 메일 행 순서를 변경하지 않는다.

키보드/터치 대안으로 선택 영역의 제목 옆에 이동 대상 이름과 ‘앞으로/뒤로’(←/→) 버튼을 제공한다. 열 이름을 누르거나 초점을 두면 그 열을 이동 대상으로 표시한다. 첫 열의 앞으로, 마지막 열의 뒤로는 비활성화한다. 이름 버튼에 초점을 둔 상태의 `Alt+←/→`로 한 칸, `Alt+Home/End`로 맨 앞/끝으로 이동한다. 기존 `Alt+↑/↓`도 보조 단축키로 유지한다. 이동 후 같은 열로 초점을 유지하고 변경 위치를 상태 알림으로 읽는다. 이동 대상 표시는 필터·선택 개수와 별개이며 명확한 테두리로 구분한다.

열 순서는 이름/화면 위치 대신 안정된 `column_id` 배열로 보관한다. 추출 항목 선택 집합과 순서는 분리한다. 새 항목은 현재 순서의 끝에 추가하고, 해제한 항목은 제거하며, 재선택은 끝에 추가한다. 미리보기와 저장 확인, 최종 `ExportPlan.columns`는 이 배열의 순서를 사용한다. 서버는 ID 누락/중복/알 수 없는 열을 검증하고, 미리보기 요청에 열 구성 버전을 포함해 늦은 응답이 최신 순서를 덮지 않게 한다. 실제 저장 후에는 Excel 열 이름뿐 아니라 해당 열의 값도 같은 순서인지 검증한다.

미리보기는 25행 단위이고 Excel은 전체 메일을 한 행씩 저장한다. 미리보기/실제 Excel은 동일한 열 구성과 값 보정을 사용한다. 미리보기의 검색이 전체 저장으로 오해되지 않도록 전체 저장 행 수를 항상 표시한다.

## 6. 통계 정의와 추천 v1

### 6.1 집계 단위

- `mail_id`: 이번 입력의 EML 식별자. 상대 경로와 입력 인덱스로 구분한다.
- `document_id`: EML의 본문 전체를 한 문서, 각 DOCX 첨부를 별개 문서로 본다. 이름이 같은 첨부도 MIME 위치로 구분한다.
- `occurrence`: 원본 표의 논리적인 항목 셀과 값 셀 한 쌍. 원본 위치를 포함한다.
- `field_id`: 정규화한 항목명에 대한 안정된 식별자. 시스템 열과 사용자 항목의 이름 공간을 분리한다.

같은 메일의 본문과 DOCX에 교육명이 있으면 발견 메일 1개, 발견 문서 2개다. 한 문서의 여러 표에 동일 항목이 있으면 해당 문서의 반복으로 센다. 같은 값이 반복돼도 등장 횟수는 보존한다.

병합 셀 및 중첩 표 순회로 같은 물리 셀을 두 번 읽는 것은 등장 2회로 세지 않는다. HTML/Word 파서에서 위치를 기준으로 중복 순회를 제거한다. Word 외부 셀에 내부 표 텍스트를 합친 뒤 내부 표도 다시 항목으로 읽는 일을 막는다.

### 6.2 필드별 통계

| 필드 | 정의 |
|---|---|
| `mail_count` | 항목이 한 번 이상 등장한 서로 다른 EML 수 |
| `total_mail_count` | 이번 분석에 입력된 모든 EML 수. 오류 포함이며 별도 오류 수 표시 |
| `document_count` | 항목이 한 번 이상 등장한 문서 수 |
| `occurrence_count` | 물리 위치 중복을 제거한 전체 등장 수 |
| `single_document_ratio` | 등장 문서 중 항목이 정확히 1회 나온 문서 비율 |
| `median_occurrences`, `max_occurrences` | 등장 문서별 횟수의 중앙값과 최대값 |
| `filled_ratio` | 등장 기록 중 정규화한 값이 비어 있지 않은 기록 비율 |
| `distinct_value_count` | 정규화한 서로 다른 비어 있지 않은 값 수 |
| `examples` | 최초 등장 순의 서로 다른 값 최대 3개 |

‘18/20개 메일’의 분모는 전체 입력 수다. 표 없음과 읽기 실패는 항목 값이 비어 있음과 구분하여 결과 요약/상세에 표시한다. 분모 0은 비율 0으로 위장하지 않고 ‘계산 불가’로 반환한다.

동일 EML 바이트를 여러 경로로 넣은 경우 원본 행은 모두 보존한다. 별도 `effective_mail_count`는 원본 EML 해시 그룹당 1회로 계산하며 추천과 공통성 정렬에 사용한다. UI는 원래 발견 수와 ‘동일 원본 중복 N개’를 함께 설명한다. 다른 메일에 복사된 동일 첨부는 문서 콘텐츠 해시로 표시하되, 동일 첨부라는 이유만으로 서로 다른 메일까지 합치지 않는다. 인용/전달된 과거 메일의 의미상 중복 판정은 후속 범위다.

### 6.3 설명 가능한 초기 규칙

추천은 ‘유효함 확정’이 아니라 검토 우선순위다. 확률 또는 0~100점 정확도로 표현하지 않는다. 임계값은 합성 검증용 초기값이며 실제 파일 평가 후 조정한다.

공통 후보는 아래 조건을 모두 만족한다.

1. `effective_mail_count >= 2`.
2. `single_document_ratio >= 0.8`.
3. `filled_ratio >= 0.8`.
4. 신뢰 가능한 항목/값 표에서 나온 항목이며, 해결되지 않은 구조 확인 출처가 섞여 있지 않음.

드문 항목: `effective_mail_count == 1`. 반복 많음: 등장 문서 중 2회 이상인 비율이 20% 초과. 구조 확인: 일반 데이터 표/레이아웃/불명확한 표에서 나온 후보를 포함. 항상 같은 값, 긴 항목명, 숫자로만 된 항목명은 참고 단서로만 표시한다.

기본 정렬은 공통 후보 여부 내림차순 → `effective_mail_count` 내림차순 → `single_document_ratio` 내림차순 → `filled_ratio` 내림차순 → 최초 발견 순이다. 가중 합산 점수는 도입하지 않는다. 반복 적은 순에서는 중앙값 오름차순, 최대값 오름차순, 발견 메일 수 내림차순을 사용한다.

동일 EML 중복은 반복·채움 비율에도 한 해시 그룹의 대표만 반영한 추천용 통계를 사용한다. 화면의 원본 통계와 추천용 통계가 다르면 두 수치를 상세에서 구분한다.

샘플이 한 개이거나 공통 후보가 없어도 전체 목록과 드문 항목을 즉시 볼 수 있다. 빈 추천 화면으로 검토를 막지 않는다. 단일 표의 ‘특별 요청’처럼 드물지만 중요한 필드가 선택 가능한지 수용 테스트에 포함한다.

## 7. 표 구조 처리

파싱 결과를 바로 하나의 dict로 합치지 않고 `ParsedTable` → `FieldOccurrence` → `FieldStatistics` → 저장용 레코드 순서로 처리한다.

표 유형:

- `key_value`: 항목/값 헤더 쌍 또는 명확한 반복 항목/값 구조. 짝수 열이라는 이유만으로 확정하지 않는다.
- `records`: 머리글 뒤로 여러 데이터 행이 이어지는 명단/내역 표. 사람 이름이나 주문번호를 공통 필드명으로 즉시 승격하지 않는다.
- `layout`: 배치/서명 용도로 의심되는 표. 검토할 수 있게 남긴다.
- `uncertain`: 확신하기 어려운 표. ‘구조 확인’에서 확인 가능.

판정 근거와 원본 격자를 보존한다. 불명확한 표의 기존 방식 후보도 ‘전체/구조 확인’에서 접근 가능하게 하되 공통 후보에 포함하지 않는다. 일반 데이터 표를 별도 행 구조로 Excel에 취합하는 기능은 후속 범위다. v1은 원본 표와 후보를 확인하고 명시적으로 항목/값 해석을 선택하는 데까지 제공한다.

문법적으로 파싱할 수 없는 파일은 후보 없는 오류 기록으로 남긴다. 정상인 다른 메일과 표의 분석은 계속한다. fuzzy matching/자동 유사 이름 병합은 v1에서 하지 않는다.

초기 판정 순서는 사용자 지정 → 명시적인 항목/값 헤더 → 데이터 표/레이아웃의 구조 단서 → 여러 문서에서 반복되는 항목/값 양식 → 불명확 순이다. HTML `th`/`thead`, Word 헤더 행 속성과 병합 범위를 파싱 결과에 보존한다. 일반 머리글 존재만으로 데이터 표를 확정하지 않으며, 항목/값 헤더 사전을 먼저 적용한다.

헤더가 없는 양식은 서로 다른 EML 원본 2개 이상에서 정규화한 왼쪽 항목명이 순서대로 2개 이상 일치하는 경우를 반복 양식 근거로 사용한다. 표 단위로 최소 절반의 항목명이 일치해야 하며 이미 데이터 표/레이아웃의 모순되는 근거가 있으면 불명확으로 둔다. 오른쪽 값의 동일 여부는 이 승격 조건에 넣지 않는다. 하나의 표에 병합/중첩 때문에 열 쌍이 어긋나는 부분이 있으면 그 부분의 후보는 구조 확인으로 남긴다. 이 초기 규칙은 판정 이유와 규칙 버전을 기록하고 합성/실제 사례로 보정한다.

## 8. 처리 모델과 API 계약

### 8.1 작업/분석/저장 분리

세 카드의 이름을 처리 로직 분기로 직접 사용하지 않는다. 카드에서 명시적인 `ProcessingPlan`을 만들고, 완료 결과는 분석 능력을 `AnalysisCapabilities`로 기록하며, 저장 시 `ExportPlan`을 검증한다.

`ProcessingPlan`: `mode`(list/archive/analyze/custom), `collect_mail_index`, `collect_attachment_index`, `prepare_attachment_files`, `prepare_body_text`, `extract_attachment_text`, `table_sources`.

메일 목록은 항상 공통 생성한다. 목록 모드는 첨부 수/이름에 필요한 MIME 메타데이터만 읽으며 `payload` 호출이나 본문 렌더링을 하지 않는다. EML 파일 자체를 읽고 MIME을 파싱하는 I/O는 여전히 발생하므로 ‘헤더만 디스크에서 읽는다’거나 ‘즉시 완료’라고 보장하지 않는다.

정확한 첨부 크기에 디코딩이 필요하면 목록 모드에서는 `size_bytes: null`, 화면은 ‘확인 안 함’으로 둔다. 0바이트와 미확인을 혼동하지 않는다. 표만 분석하는 경우에는 DOCX payload만 디코딩한다. 일반 첨부 원본 준비는 해당 옵션을 켰을 때 수행한다.

`ExportPlan`: 목록/첨부 목록/첨부 원본/본문 TXT/첨부 TXT/표 Excel 포함 여부, 표 열 구성, 저장 경로, 다운로드 묶음 선택.

준비된 산출물을 제외하거나 표 열만 바꾸는 것은 재분석 없이 적용한다. 새로운 내용 분석이나 준비하지 않은 원본 저장을 켜면 ‘추가 처리가 필요합니다’를 표시한다. v1은 전체 재분석을 허용하며 부분 캐시 재사용을 약속하지 않는다. 원본 입력 접근과 변경 여부를 검증한다.

재분석이 필요할 때 설정 편집 중에는 새 구성 저장을 막고 ‘설정 취소’로 이전 완료 상태를 복원할 수 있다. 기존 완료 결과는 새 분석 성공 전까지 보유한다. 같은 입력의 재분석 성공 시 안정된 필드 ID로 선택/순서/이름/사용자 열을 복원하고, 사라진 항목을 알린다. 입력 자체가 바뀌면 새 작업으로 시작한다.

### 8.2 데이터 계약

`ParsedTable`: `table_id`, `mail_id`, `document_id`, `source_kind`, `attachment_index`, `source_name`, `table_index`, `cells`(행/열/병합/헤더 여부/텍스트), `shape`, `shape_reasons`, `override`.

`FieldOccurrence`: `occurrence_id`, `field_id`, `original_key`, `normalized_key`, `value`, `mail_id`, `document_id`, `table_id`, `key_position`, `value_position`, `shape_status`.

`FieldStatistics`: 6장의 통계, 추천용 통계, `source_counts`, `flags`, `recommendation_reasons`, `first_seen_order`.

저장 레코드는 등장 기록에서 만든다. 선택하지 않았다고 원본 기록을 삭제하지 않는다. 값의 중복 제거는 통계를 만든 뒤 출력 투영에서 적용한다. 반환할 문자열을 합쳐서 원래 등장 횟수를 추정하지 않는다.

### 8.3 API 초안

기존 세션 토큰/Origin 검사/dataset 버전 검사를 유지한다. 분석 세션마다 아래 조회를 추가한다.

- `POST /api/fields`: `dataset`, `source_scope`, `query`, `search_values`, `category`, `sort`, `page`, `page_size` → 후보 페이지, 카테고리별 수, 선택 수와 전체 수, 집계 범위.
- `POST /api/field-detail`: `dataset`, `field_id`, `source_scope`, `page` → 전체 통계, 추천 근거, 출처 페이지와 원본 표 참조.
- `POST /api/table-detail`: `dataset`, `table_id` → 안전한 원본 격자와 판정 이유.
- `POST /api/table-interpretation`: `dataset`, `table_id`, `interpretation` → 새 분석 버전과 재계산된 필드 정보. 이전 버전의 저장을 거부한다.
- `POST /api/export-plan`: `dataset`, `export_plan` → 검증된 저장 예정 산출물, 개수, 준비되지 않은 기능.

기존 preview는 선택한 열의 25행 조회를 계속 담당한다. 추천 통계는 미리보기 페이지가 아닌 전체 분석 결과에서 계산한다. 저장 시에도 서버에서 동일한 검증을 재실행한다.

항목 목록은 기본 50개씩 조회하고 1,000개 항목을 한 번에 DOM에 넣지 않는다. 검색은 서버의 전체 후보 범위에서 수행한다. 상세 출처도 페이지 단위로 읽는다. 원본 표/등장 기록은 세션 작업 영역에 저장하고 목록에는 집계만 제공한다. 최초 구현은 로컬 SQLite 등을 사용할 수 있으며 종료 시 세션 자료를 정리한다.

### 8.4 진행 상태 계약

분석과 저장을 모두 백그라운드 작업으로 실행한다. 시작 요청은 `job_id`를 신속하게 반환하고, 기존 `/api/state`에 구조화한 `progress`를 추가한다. 로그 문자열을 파싱해 퍼센트를 만들지 않는다.

`JobProgress`: `job_id`, `revision`, `operation`(analyze/export), `status`(preparing/running/cancel_requested/cancelled/completed/failed), `phase_id`, `phase_index`, `phase_count`, `phase_label`, `completed_units`, `total_units`(미확정이면 null), `unit`(mail/field/row/file/byte), `current_file`, `current_operation`, `success_count`, `warning_count`, `failure_count`, `elapsed_ms`, `updated_at`, `can_cancel`, `error`.

`completed_units`는 현재 단계에서 단조 증가하며 `0 <= completed_units <= total_units`를 지킨다. `total_units: null`과 0을 구별한다. 단계 전환 시 단위/분모/분자를 한 상태 갱신으로 교체한다. 정상 종료의 데이터셋/결과 경로는 최종 완료 응답에 포함한다. 같은 작업의 낮은 `revision` 및 이전 `job_id` 응답은 화면에 적용하지 않는다.

상태 조회는 실행 중 약 500ms~1초 간격으로 하되 요청을 중첩하지 않는다. 서버는 처리량 변화와 별도로 생존 상태를 갱신한다. 응답이 15초 이상 오지 않으면 마지막 개수와 표시줄을 유지하며 ‘상태 응답이 지연되고 있습니다’를 표시한다. 응답 지연을 실패나 완료로 추정하지 않는다. 재연결 시 최신 서버 상태로 복구한다. 중지 요청은 `job_id`로 식별하고 재전송되어도 같은 요청으로 처리한다.

분석기/내보내기는 공통 진행 콜백으로 의미 있는 경계에서 이벤트를 발행한다. 셀마다 UI 이벤트를 만들지 않으며 상태 갱신은 모아 전달한다. 저장은 현재 동기 응답 방식에서 worker 실행으로 확장하고, 중지 확인을 행/파일/ZIP 청크와 최종 확정 직전의 안전한 경계에 추가한다.

## 9. 새 GUI의 출력 계약

| 산출물 | 조건 | 내용 |
|---|---|---|
| `EmailTools_List.xlsx` | 항상 | `MailList` 시트, 첨부 목록 포함 시 `AttachmentList` 시트 |
| `tables/EML_Table_Result.xlsx` | 표 Excel 선택 | 기존 `Result` 시트 형식, 선택한 열 |
| `mails/<메일ID>/attachments/*` | 첨부 원본 저장 | 원본 형식 유지, 충돌 회피 |
| `mails/<메일ID>/mail.txt` | 본문 TXT 저장 | 헤더와 본문 |
| `mails/<메일ID>/text/*` | 첨부 TXT 추출 | 지원 첨부의 추출 텍스트 |
| `summary.csv`, `attachments.csv` | 기존 호환 출력 | 기존 열과 의미 유지 |
| `processing.log`, `.emailtools-job.json` | 항상 | 작업 옵션, 버전, 상태, 추천 규칙 버전 |
| `EmailTools_Result.zip` | 다운로드 묶음 | 생성된 전체 결과 |

`MailList`: 원본 경로, 제목, 발신자, 수신자, 메일 날짜, 첨부 개수, 상태, 오류. 날짜는 원문과 시간대 정보를 보존하고 정렬용 파싱 값은 별도로 관리한다.

`AttachmentList`: 원본 메일, 첨부명, 형식, 크기(미확인 허용), 원본 저장 상대 경로, 텍스트 추출 상태, 표 분석 상태, 오류. `attachments.csv`는 목록 모드에서도 기존 이름/형식 메타데이터를 기록할 수 있으나 크기 미확인은 빈 셀로 출력한다. 첨부 없음이면 헤더만 기록한다.

경로 미지정 다운로드는 목록만 모드에서 목록 Excel을 주 다운로드로 제공하고 전체 ZIP도 받을 수 있다. 첨부/표/텍스트를 포함하면 ZIP을 주 다운로드로 제공한다. 세션 종료 시 임시 다운로드가 삭제되는 기존 안내는 유지한다.

기존 CLI 옵션, 기본 동작, 호환용 진입 파일의 결과는 유지한다. 새 CLI를 제공할 때 `--mode list|archive|analyze`를 추가하며 기존 개별 플래그와 함께 쓰면 모호한 덮어쓰기 대신 사용 오류를 반환한다. 기존 `--all`은 본문/첨부/텍스트/표 네 기능의 의미를 유지한다. 새 GUI 세 카드 의미와 혼동하지 않도록 CLI 도움말에 명시한다.

## 10. 글자 크기와 반응형 기준

- 본문/항목명/표 셀/주요 버튼: 14px. 입력창/검색창: 16px. 머리글: 14px. 보조 안내: 최소 12px. 구역 제목: 18px.
- 공통 토큰을 사용하고 요소마다 9~11px를 재지정하는 스타일을 제거한다.
- 기본 행 높이 최소 44px, 여러 줄이면 내용에 맞게 늘린다. 버튼 높이는 최소 40px, 터치 환경 44px.
- ‘글자 크기: 기본/크게’ 제공. 크게는 읽기 텍스트를 약 2px 늘리고 행/여백도 조정한다. 글자 크기 설정만 로컬에 기억하며 메일 값은 브라우저 저장소에 저장하지 않는다.
- 주요 텍스트와 안내는 배경에 대해 대비 4.5:1 이상을 설계 목표로 한다. 상태는 색과 문구를 함께 사용한다.
- 검토 화면은 모든 너비에서 위쪽 선택 열과 아래쪽 후보를 함께 유지한다. 각 영역의 항목 버튼은 가로로 흐르다가 자동 줄바꿈한다. 남은 화면 높이를 나눠 사용하고 필요한 경우 목록 안에서만 세로 스크롤한다. 작업 선택 화면의 카드는 기존처럼 좁은 화면에서 세로로 배치한다.
- 가로 스크롤은 표 영역 안에서 허용한다. 페이지 전체가 가로로 밀리거나 글자를 줄여 맞추지 않는다.
- 키보드로 작업 카드 선택, 후보 추가/열 제외, 순서 이동, 상세 열기/닫기, 저장까지 진행 가능하게 한다. 필터/검색 시 초점을 잃지 않는다. 후보를 추가한 뒤에는 다음 후보 또는 검색창에 초점을 유지하며, 순서 이동 후에는 이동한 열을 해당 목록 안에서 보여준다.
- 빈 상태, 오류, 선택 변경은 적절한 상태 알림으로 읽히게 한다. 확대 200%에서도 주요 동작을 사용할 수 있어야 한다.

## 11. 구현 순서

### A. 작업 선택과 읽기 편의

세 카드, 목록 전용 처리, 목록 Excel, 조건부 결과 탭, 저장 확인, 글자 토큰, 분석·저장 진행 표시줄과 구조화된 상태/중지 계약. 가장 먼저 배포 가능한 묶음이다. 기존 추출 결과는 유지하되 구조 확인 전에는 추천 품질을 과장하지 않는다.

### B. 항목 탐색의 근거

원본 표/등장 기록 모델, 물리 셀 중복 제거, 전체 데이터 통계, 공통 후보 규칙, 검색/필터, 값 예시, 선택과 정렬 분리, 원본 출처 확인. 이 묶음 완료 후 ‘공통 후보’ UX를 활성화한다.

### C. 표 구조와 검토 완성

표 유형 판정, 구조 확인과 사용자 지정/되돌리기, 동일 EML 중복 집계, 재분석 후 선택 복원, 큰 입력 성능 검증. 표 구조와 중복 대응 전까지는 v1 스펙 전체 완료로 간주하지 않는다.

후속: 실제 파일 평가를 통한 임계값 조정, 수동 별칭/선택 템플릿 저장, 일반 명단형 표 취합, 계정 연결, 독립 Word 파일 입력. 자동 유사 이름 병합과 AI 판단은 초기 필수 기능으로 넣지 않는다.

| G02 | 메일 20개 중 정상 12/확인 2/실패 1 처리 종료 | 진행은 15/20=75%, 처리 중인 메일은 분자에서 제외 |
| G03 | 메일 처리 완료 후 항목 정리/저장 마무리 계속 | 단계 완료와 작업 완료를 구별, 결과 확정 전에 작업 완료 100% 없음 |
| G04 | 큰 첨부/느린 파일/상태 응답 지연 | 현재 파일·세부 작업·경과 시간 표시, 가짜 퍼센트 증가 없음 |
| G05 | 분석/저장 중지, 재시도, 늦게 도착한 상태 | 중지 요청과 확정 구별, 미완성 결과 미게시, 이전 결과 유지, 이전 작업 응답 무시 |
| G06 | 저장 파일 작성 → 복사 → ZIP → 최종 확정 | 선택 단계만 표시, 실제 단위 집계, 브라우저 다운로드 완료와 구별 |
| G07 | 0개 입력/파일 실패/치명적 오류/확정 직전 중지 | 0 분모 오류 없음, 실패를 성공으로 표시하지 않음, 서버 최종 상태와 일치 |
| G08 | 키보드/스크린 리더/작은 화면/움직임 감소 | 단계·수량·중지 접근 가능, 미확정에 aria-valuenow 없음, 반복 음성 알림 없음 |
| E01 | 저장 미리보기와 실제 파일 | 전체 행 수, 열 순서, 이름, 다중 값, 사용자 값 일치 |
| E02 | CSV/Excel 셀에 수식 같은 값 | 기존 문자열 처리와 셀 길이/제어문자 보정 유지 |
| E03 | 기존 CLI/BAT/포터블 | 기존 옵션/출력/오프라인 실행 회귀 없음 |
| P01 | 합성 EML 1,000개, 후보 1,000개, 등장 100,000개 | 항목은 페이지 조회, 예열 후 필터/정렬 응답 p95 500ms 이내를 초기 목표로 측정 |

P01은 시험 장비/파일 크기/메모리 사용/초기 분석 시간을 함께 기록한다. 이 목표는 검증 전 성능 보장이 아니다. 합성 데이터에는 HTML/DOCX의 공통 양식, 서명 반복, 빈 값, 고유 값, 깨진 문서, 중첩 표, 동일 EML 복사본을 포함한다.

실제 메일은 이번 설계에서 검사하지 않았다. 실제 데이터 검증 시에는 사용자가 제공한 범위에서 공통 후보의 적중/누락과 항목 선택 시간을 확인한다.

## 13. UX 시안의 범위

대화에 제공하는 시안은 합성 예시를 사용하는 상호작용 설계다. 세 작업 선택, 분석·저장 단계별 진행 표시줄과 중지/재시도, 세부 저장 옵션, 조건부 결과 화면, 항목 검색/분류/선택, 열 Drag & Drop/키보드 이동/순서 되돌리기, 출처 상세, 저장 예정 구성을 확인한다. 진행 시간과 처리 이벤트는 시안용 모의 값이며 실제 성능을 뜻하지 않는다. 파일 가져오기/실제 분석/파일 저장/재분석/원본 표 유형 지정은 실행하지 않는다.

시안의 숫자는 예시 등장 기록에서 계산한다. 본문과 Word는 문서별로 구분하며 메일 수에서는 중복 제거한다. 실제 파일 성능이나 추천 정확도를 증명하는 자료로 사용하지 않는다.

시안 검증: Edge에서 세 작업, 조건부 탭, 공통 후보 일괄 선택/되돌리기, 드문 항목 추가, 검색·출처 필터 후 선택 유지, 열 순서 유지, 0개 선택 시 명시적 표 제외, 저장 요약을 확인했다. 320/360/736/1,024/1,440px의 밝은/어두운 화면과 큰 글자 상태에서 페이지 가로 넘침 및 조작 버튼 잘림이 없음을 확인했다. 실제 제품의 수용 기준 통과를 의미하지 않는다.

진행 표시줄 시안 추가 검증: 전체량 미확정/확정, 15/20개=75%, 단계 완료와 작업 완료 구분, 중지 요청 후 확정, 처음부터 재시도, 최종 확정 중 중지 제한, 저장 중지 후 선택 보존을 확인했다. 작은 화면·큰 글자·밝은/어두운 화면·움직임 감소 환경에서도 진행 상태를 확인할 수 있다. 실제 서버 상태 지연/실패 처리와 실제 저장 취소는 구현 후 G01~G08로 검증한다.

열 순서 시안 추가 검증: Edge에서 실제 마우스 드래그로 앞/뒤 삽입과 머리글에서의 이동, 열 이름과 값의 동시 이동, 기본 메일 열 이동, 순서 되돌리기, 같은 위치/영역 밖 드롭, Escape 취소, 외부 드롭 무시를 확인했다. 키보드 이동·초점 유지·첫/끝 경계, 탐색 필터 후 순서 유지, 저장 확인의 순서 일치, 해제 후 재선택 시 끝에 추가, 작은 화면과 터치 이동 버튼도 검증했다. 실제 Excel 파일의 순서 일치는 제품 구현 후 E01/U07로 검증한다.

v4 재현 결과: 이전 열 이동 검증은 독립 페이지 중심이었고, 포함된 미리보기에서는 열 이름을 끌어도 순서가 바뀌지 않는 문제를 재현했다. 머리글 빈 영역도 이동 시작 영역에 포함되지 않았으며, ‘표 항목 찾기’에는 순서 조정 영역이 없었다. 포인터 기반 처리로 교체하고 검토 화면의 선택 열 편집을 추가했다. 위 v3의 검증 기록만으로 포함된 환경에서의 동작을 보장하지 않는다.

v4 수정 검증: sandbox iframe 안에서 검토 화면의 열 카드 이동, 머리글 빈 영역에서 시작하는 이동, 열과 값의 일치, 검토 탭/선택 유지, Escape 취소, 가장자리 가로 스크롤을 확인했다. 실제 터치 입력의 드래그 및 취소도 통과했다. 재확인용 시안은 예시 공통 항목 4개가 선택된 검토 화면부터 열리며, 실제 제품의 초기 선택 규칙은 변경하지 않는다.

v5 수정 검증: 320/360/736/1,024/1,440px에서 6개 열이 6행 1열로 배치되고 가로 넘침이 없음을 확인했다. sandbox iframe 안에서 마우스의 위/아래 드래그, 가로 삽입선, ↑/↓ 버튼, Alt+↑/↓, 경계 버튼 비활성화, 초점 유지와 되돌리기를 검증했다. 검토 탭과 선택 개수가 유지되며 미리보기의 열 이름·값이 같은 순서로 이동한다. 터치 드래그와 별도 탭으로 버튼 이동도 확인했다. 자동화에서는 주입한 터치 드래그 종료 후 500ms 간격을 두고 버튼을 검증했다. 밝은/어두운 화면과 좁은 화면의 세로 목록을 시각적으로 확인했다.

v6 수정 검증: sandbox iframe의 1,024×800/1,440×900/736×768/360×844/320×720 화면에서 두 목록과 하단 동작이 페이지 스크롤 없이 들어가는지 확인했다. 큰 글자에서도 두 목록의 조작 영역이 유지된다. 선택된 후보 숨김, 추가·제외·재추가, 검색·분류·출처 변경 후 선택/순서 보존, 공통 후보 일괄 추가와 되돌리기, 모든 후보 선택 후 빈 상태를 검증했다. 출처 상세는 후보 영역에서 열리며 선택한 열은 유지된다. 마우스 드래그·키보드 이동과 목록 내부 자동 스크롤·취소, 실제 터치 입력의 드래그·추가·제외, 미리보기의 열과 값 및 저장 구성 순서도 확인했다. 밝은/어두운 화면과 좁은 터치 화면을 시각적으로 확인했다. 실제 파일 분석과 Excel 생성은 시안 검증 범위에 포함하지 않는다.

v7 수정 검증: sandbox iframe 안에서 320/360/736/1,024/1,440px의 자동 줄바꿈과 목록 가로 스크롤 없음, 큰 글자와 한 화면 조작을 확인했다. 버튼 크기를 유지하며 포인터를 따라 움직이는 복제 모양, 원래 자리 표시, 줄을 넘는 삽입, 후보 드래그 추가와 선택 열 드래그 제외, 기본 정보 제외 방지, Escape 취소, 클릭·키보드 대안과 저장 순서를 검증했다. 툴팁의 hover/키보드 초점/터치 탭 및 통계·값·출처 표시를 확인했다. 터치 드래그는 목록 가장자리 자동 스크롤 후 표시된 삽입선과 같은 위치에 놓이는지 확인했다. 포함된 화면의 포인터 해제 좌표 차이에 대비하여 마지막으로 표시한 포인터 위치를 드롭 판정에 사용한다. 밝은/어두운 화면 및 이동 중인 버튼 모양을 시각적으로 확인했다. 실제 Excel 생성은 제품 구현 후 검증한다.
