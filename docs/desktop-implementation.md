# 2.1 계획의 Windows 앱 적용

기준: product-spec-v2.1.md 개발 전 설계안 v7. 원래 계획 파일은 보존하고 적용 범위를 여기에 기록한다.

| 웹 계획의 전제 | Windows 적용 |
|---|---|
| 브라우저·HTTP API | Qt Widgets + QThread signals |
| HTML Pointer Events | Qt QDrag·내부 MIME·키보드·머리글 이동 |
| 브라우저 업로드 | QFileDialog·경로·파일/폴더 Drag & Drop |
| 다운로드 전용 임시 결과 | 영구 폴더 저장·탐색기/Excel 열기 |
| 모바일 320px | 최소 1000×720 논리 픽셀의 데스크톱 공간 |
| 기본 14px 이상 | 사용자 추가 요청으로 본문 13px·입력 14px |
| API dataset 검사 | 단일 worker·세션별 dataset/MIME 검사 |
| SQLite 선택지 | 세션 메모리 모델, 50개씩 조회 |

A: 세 작업, 목록 전용 처리, 목록 Excel, 조건부 탭, 저장 확인, 진행·중지.
B: 원본 셀·등장 기록, 출처별 통계, 추천 근거, 검색·필터, 독립된 선택 순서, 원본 확인.
C: 초기 구조 판정·수동 변경/복구, 동일 EML 구분, 재분석 선택 복원, 합성 성능 측정.
기존 CLI·BAT·결과 형식은 보존하며 기본 실행만 네이티브 앱으로 전환했다.

## 검증 범위

Python 회귀, Windows Qt 이벤트 루프·키보드·드래그 이벤트·머리글 이동·실제 Excel 값 일치를 검증했다.
독립 배포 검증은 압축 해제된 경로의 내장 Python과 UI 런타임을 사용한다.

Computer Use native pipe가 재시도·초기화 뒤에도 연결되지 않았다.
외부 마우스/물리 터치, 스크린 리더, 200% Windows 배율은 이번 검증에 포함되지 않았다.
Qt drag 이벤트는 검증했으나 OS 포인터 전달 부분은 별도 수동 확인이 필요하다.

표 분류는 초기 규칙이며 모든 비정형 문서의 구조를 확정하지 않는다.
원본 확인과 해석 변경을 제공한다. 실제 사내 메일의 추천 적중률은 측정하지 않았다.
P01은 합성 HTML 메일 1,000개·후보 1,000개·등장 100,000개를 측정했다.
desktop-benchmark.json에 장비·입력 크기·메모리·초기 분석 시간·조회 지연을 기록했다.
합성 성능을 실제 대용량 첨부 처리 시간으로 일반화하지 않는다.

웹/모바일 수용 기준 전체 통과를 뜻하지 않는다. 계정 연결, 독립 Word 입력, OCR,
명단형 표의 행 단위 취합, AI/유사 이름 자동 병합, 선택 템플릿 영구 저장은 후속 범위다.
