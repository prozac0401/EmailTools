# 검증 방법

## 2.1.1 Windows 앱 · 2026-09-10

기존 회귀를 포함한 Python 테스트 **72개 통과**. Windows Qt smoke 검사 **7개 시나리오 통과**.
기본 글꼴을 본문 13px·입력 14px로 조정한 뒤 같은 앱 검사도 통과했다.

```bat
runtime\python\python.exe -X utf8 -m unittest discover -s tests -v
run.bat --desktop-smoke .desktop-test
runtime\python\python.exe -X utf8 tools\benchmark_desktop.py
runtime\python\python.exe -X utf8 tools\build_portable.py
```

새 검증은 목록 모드의 본문/첨부 미디코딩, 목록 XLSX, 반복/출처/동일 EML 집계,
명단형 표의 추천 제외와 수동 해석, HTML 병합·중첩의 물리 셀 소유,
여러 입력, 실제 단계 수량, 저장 취소 시 staging 정리, 수식 모양의 문자열을 다룬다.

Qt smoke는 실제 이벤트 루프에서 분석·저장을 실행하고 후보 추가, Qt drag 이벤트의 MIME·버튼 이미지·삽입,
키보드·머리글 순서 변경, 필터 후 선택 보존, 미리보기와 Excel 전체 값 일치,
1000×720 큰 글자 배치와 HTTP 서버 미사용을 검사한다. `docs/desktop-images`는 Windows Qt 캡처다.
외부 Computer Use 서비스가 연결되지 않아 OS 마우스·물리 터치 조작은 검증하지 않았다.

파일 입력 오류 조사에서 `QDragMoveEvent`가 거부되는 문제와 탐색기의 여러 ‘경로로 복사’ 값이
단일 경로가 되는 문제를 수정 전 테스트로 재현했다. `test_desktop_input.py`의 6개 검사는
진입·이동·놓기 이벤트를 Qt에 전달하여 모두 허용되는지 확인한 뒤 실제 EML 분석까지 실행한다.
파일/폴더 선택 버튼의 반환 경로, 한글·공백·특수문자, 대문자 확장자, 하위 폴더,
여러 인용 경로, 없는 파일의 사전 거부, 선택 취소 시 입력 보존도 검사한다.
같은 6개 검사는 Windows 플랫폼의 `pythonw.exe`에서 표준 출력/오류가 없는 상태로도 통과했다.
게시된 v2.1.0 ZIP을 별도 폴더에 풀어 같은 실패를 재현했으며, 두 수정 모듈을 적용한 뒤
그 배포본의 내장 `pythonw.exe`로 6개 검사가 모두 통과하는 것도 확인했다.
파일 선택 대화상자의 반환값은 테스트에서 제공하므로 Windows 탐색기 창 자체의 조작 검증은 아니다.

`test_desktop_results.py`는 분석 버튼에서 결과 화면 자동 표시까지 검사한다.
새 입력을 가리던 이전 검색 조건, 표가 없는 메일의 안내, 결과 표시 중 예외의 화면·로그 기록,
분석/표시 실패 시 이전 결과·선택 열·첨부 임시 파일 보존을 포함한다.
실제 발생 원인이 확인되지 않은 화면 예외는 테스트에서 주입하여 오류 처리 경계를 검증한다.
UI 갱신은 GUI 스레드에서 실행되는지도 확인한다.
결과 관련 6개 검사도 Windows 플랫폼의 `pythonw.exe`에서 표준 출력/오류 없이 통과했다.
v2.1.1 포터블 빌드는 독립된 압축 해제 경로에서 데스크톱 회귀 검사 21개를
내장 `pythonw.exe`로 실행하며, 콘솔 없는 실행과 결과를 확인한 뒤 ZIP을 확정한다.

성능: 합성 HTML 메일 1,000개 / 후보 1,000개 / 등장 100,000개에서 예열 후 조회 p95 **4.763ms**,
Python 할당 최고치 **119.37 MiB**. 초기 분석은 메모리 계측을 켠 상태에서 **94.832초**였다.
이는 Python 메모리 계측 오버헤드를 포함하며 실사용 처리 시간 보장이 아니다. 장비·조건은 `desktop-benchmark.json`에 기록했다.

## 2.0 웹 UI의 기존 검증 기록

모든 데이터는 임시 폴더에서 생성한 합성 EML/DOCX/XLSX/PPTX/PDF다. 개인 메일을 사용하지 않는다.

2026-09-08 통합 검증: Python 자동 테스트 **51개 통과**, 브라우저 회귀 테스트 통과.
15가지 기능 조합은 하나의 매개변수 테스트 안에서 모두 검증한다.

```bat
runtime\python\python.exe -X utf8 -m unittest discover -s tests -v
```

| 테스트 | 검증 범위 |
|---|---|
| `test_app.py` | 기존 첨부 콘솔, 한글 인코딩, 중복/위험 파일명, MIME, Office/PDF |
| `test_table_to_excel.py` | 기존 표 콘솔, HTML/DOCX 매핑, 값 병합, 셀 보정과 수식 방지 |
| `test_table_gui.py` | 열 선택/복원/순서, XLSX 일치, 페이지 전체 저장, HTTP 격리, BAT GUI 시작/종료 |
| `test_unified.py` | 15개 기능 조합, MIME/payload 한 번 읽기, 옵션별 출력, 중첩 메일 경계, 부분 오류, 입력 보존, 저장 실패/반복 저장, 검색 제외, 취소/재분석 |
| `test_portable.py` | 이전 도구 폴더 없는 배포, 한글·공백·특수문자 경로, 통합 CLI, 오프라인 ZIP/기존 런타임 이행, 손상 ZIP 복구 |

`test_portable.py`는 실제 내장 Python과 프로그램을 별도 임시 폴더로 복사해 BAT를 실행한다.
설치 테스트에는 로컬 ZIP 또는 기존 런타임을 제공하여 네트워크를 사용하지 않는다.

브라우저 검증은 개발용 Node.js, Playwright와 설치된 Edge를 사용한다.

```bat
node tests/gui_smoke.cjs [Playwright 모듈 경로] [스크린샷 저장 폴더]
```

다음 동작을 실제 화면과 다운로드 파일로 검증한다.

- 샘플 분석, 열 추가/제외/복원/순서 변경 및 중복 이름 거부
- 원본 전체와 저장할 표 전환, XLSX 헤더/전체 값과 미리보기 일치
- 빈 열 선택의 저장 차단, 업로드와 오류 복구, 외부 문자열의 HTML 비실행
- 옵션 변경 시 저장 차단, 현재 입력 재분석, 메일/첨부 목록
- 전체 처리 ZIP의 본문/원본/텍스트/Excel 구성
- 표 추출을 끈 경우의 저장 및 ZIP에서 Excel 제외
- 열 설정 접기·펼치기, 드래그와 방향키·Home/End로 너비 조절
- 20개 항목이 있는 메일의 열 목록 내부 스크롤과 작업 영역 높이 유지
- 320/390/800/1024/1440/1920px 너비의 배치와 가로 넘침
- 1280×600 창의 저장 버튼 접근과 미리보기 하단 영역 유지
- 브라우저 오류, 정상 서버 종료

상단 소개·슬로건 제거 후 320/390/800/1440px 배치와 ‘메일 불러오기’ 옆 샘플 버튼도
실제 브라우저에서 확인했습니다. 설명서의 화면 예시는 같은 UI에서 합성 메일로 다시 촬영했습니다.

Python 테스트는 Windows에서 실행해야 BAT 관련 검증도 수행된다.
브라우저 테스트는 기본 `msedge` 채널이며 `EMAILTOOLS_BROWSER` 환경변수로 다른 설치 채널을
지정할 수 있다. Node.js/Playwright는 사용자 실행 의존성이 아니다.
